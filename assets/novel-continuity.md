# 设定圣经与连续性（Continuity）

长篇最常见的崩坏不是文笔，而是**自相矛盾**：人物状态、时间、能力、称呼、伏笔。

## 文件职责

| 文件 | 记什么 | 谁更新 |
|---|---|---|
| `story/premise.md` | 立意、主题、卖点 | 构思阶段 |
| `story/outline/` | 卷/幕/章结构 | 大纲阶段 |
| `story/characters/` | 人物卡与前史 | 人物阶段 |
| `story/world/` | 地理、势力、规则、术语 | 随剧情增量 |
| `story/timeline.md` | 事件发生的顺序与日期 | 每章写后 |
| `story/foreshadowing.md` | 伏笔：埋设章、回收章、状态 | 每章写后 |
| `story/notes/state.md` | 此刻：人物在哪、伤/物/关系/知情状态 | 每章写后 |

## 写前：章节 brief（必做）

在动笔前，先给用户 5 行以内的 brief，确认后再写正文：

1. 本章目标（主角要拿到什么 / 阻止什么）
2. 视角人物与地点、时间（距上一章多久）
3. 在场人物及其当前状态（伤、物、关系、知道什么）
4. 本章要埋/要收的伏笔
5. 章末钩子

发现问题（时间对不上、人物不该在场、能力越界）先说明冲突，再给两个修正方案。

## 写后：更新协议

按顺序更新，缺一不可：

1. `story/timeline.md`：追加“第 N 章 / 时间 / 事件 / 影响”。
2. `story/foreshadowing.md`：新埋的加一行；已回收的改状态与回收章。
3. `story/notes/state.md`：在场人物状态、物品去向、关系变化、谁知道什么。
4. `story/world/`：新地点、新规则、新术语（只记会影响后文的）。
5. `story/characters/`：人物卡里“首次出场/结局/弧光进度”有变化才改。

## 巡检清单

1. 时间：本章与上一章间隔是否与文中线索一致？
2. 地点：从 A 到 B 需要多久？是否与时间线冲突？
3. 伤势与体力：上一章的伤在这一章是否消失得没有解释？
4. 物品：关键道具在谁手里？是否凭空出现/消失？
5. 知情：角色是否知道了不该知道的信息？
6. 能力：是否越过了人物卡里的能力边界？
7. 称呼：亲属、官职、绰号是否前后一致？
8. 人数与阵营：死了的人是否又出现？
9. 伏笔：本章埋的线是否登记？该收的线是否收了？
10. 视角：是否写了视角人物看不到的事？
11. 季节/天气/节日：与时间线是否一致？
12. 术语：同一概念是否用了两个名字？

## 工具

在项目根目录运行：

```bash
node tools/novel.mjs stats      # 章节字数与总进度
node tools/novel.mjs check      # 人物/伏笔/章节结构巡检
node tools/novel.mjs foreshadow # 伏笔回收状态
node tools/novel.mjs toc        # 生成目录
```

## 冲突处理

- 以**已经定稿/发布**的章节为准，改动成本最低的一方让步。
- 必须改旧设定时，先列出影响面（哪几章、哪几个人物、哪条伏笔），再改。
- 不确定的细节，宁可在 `story/notes/` 里留“待定”，也不要写死。
