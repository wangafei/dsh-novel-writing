# 人物设定（Characters）

人物不是标签集合，而是**在压力下做选择的方式**。设定卡只记录“会改变选择的变量”。

## 先读

`story/premise.md`（主题决定了人物的弧光方向）→ `story/outline/`（人物要在哪些节点做选择）→ `story/characters/index.md`。

## 三层人物

1. **主角**：承担主题。必须有 want（表层目标）与 need（真正缺口）的错位。
2. **反派 / 对抗力量**：不是“坏人”，是**主角需求的镜像反面**。他要有一个主角无法反驳的理由。
3. **关键配角 3–5 人**：每人承担一种功能——镜子（照出主角）、阻力（拖慢主角）、代价（代表失去）、信息（推动认知）、出口（提供另一种活法）。
4. **群像**：只给“一个动作 + 一个标志”，不写小传。

每新增一人先问：删掉他，故事会损失什么？答不上来就删。

## 人物卡模板

```markdown
# 姓名

- 年龄 / 身份：
- 外貌标志（一个即可）：
- 想要（want）：
- 需要（need）：
- 最大缺陷：
- 秘密（读者何时知道）：
- 恐惧：
- 能力边界（能做什么、绝不能做什么）：
- 弧光：从 ___ 到 ___，转折点在第 ___ 章
- 关系：与 ___ 是 ___（动词），因为 ___
- 语言风格：句长、口癖、绝不说的话
- 首次出场：第 ___ 章
- 结局：

## 三件事
1. 他做过的最不体面的事：
2. 他绝不会做的事：
3. 他在压力下会重复犯的错：
```

## 工作流

1. 先定主角与反派，确保两人**互为镜像**（同一困境的两种答案）。
2. 用“三件事”反推人物，比形容词有效。
3. 配角的出场必须有**独立目的**，不是等主角来用。
4. 画关系网（见 `novel-mindmap`），每条边写动词。
5. 更新 `story/characters/index.md` 总表（姓名 / 定位 / 目标 / 秘密 / 首次出场 / 结局）。
6. 交付时给一张“人物一句话表”，让用户 30 秒内看懂谁是谁。

## 一致性检查

- 姓名、称呼、年龄、亲属关系前后一致（尤其“表姐/堂姐”类）。
- 能力边界稳定：上一章能做的事，这一章不能凭空不能。
- 口癖与句长稳定：遮住名字也能认出是谁在说话。
- 与 `story/timeline.md` 对齐：人物的年龄与事件年份对得上。
- 人物知道的信息不能超过他到场/被告知的范围。

## 反模式

- 工具人：只在主角需要时出现。
- 标签化：用一个词概括（冷酷、善良），没有行为证据。
- 反派降智：为了赢主角而犯低级错误。
- 全员同一语气：所有角色都像作者在说话。
- 小传写三千字，正文里一个选择都没体现。
